## Phase 1: Insight Surfacing Layer
**Duration:** 3-4 days
**Priority:** HIGHEST (unlocks all dream processing work)
**Complexity:** Medium

### Goal
Make Sara proactively mention insights generated by DreamingService during conversations.

### Components to Build

#### 1.1 InsightInjectionService
**File:** `backend/app/services/insight_injection.py`

**Responsibilities:**
- Retrieve relevant insights for current conversation context
- Rank insights by relevance and confidence
- Decide when to surface (not every message)
- Track which insights have been mentioned to avoid repetition

**Key Methods:**
```python
class InsightInjectionService:
    async def get_relevant_insights(
        self,
        user_id: str,
        current_message: str,
        conversation_history: List[dict]
    ) -> List[DreamInsight]:
        """
        Find insights relevant to current conversation.

        Logic:
        1. Embed current message
        2. Search DreamInsight table by semantic similarity
        3. Filter by confidence > 0.7
        4. Exclude insights mentioned in last 10 messages
        5. Return top 3
        """

    async def should_surface_now(
        self,
        insight: DreamInsight,
        conversation_context: dict
    ) -> bool:
        """
        Decide if insight is worth mentioning now.

        Criteria:
        - Not mentioned in last 24 hours
        - Confidence > 0.75
        - Topic matches current conversation (semantic similarity > 0.7)
        - Not more than 1 insight per 5 messages
        """

    async def format_insight_injection(
        self,
        insight: DreamInsight
    ) -> str:
        """
        Format insight for natural injection into conversation.

        Templates:
        - Pattern: "I've noticed you [pattern] - [observation]"
        - Trend: "Over the last [timeframe], [trend observed]"
        - Forgotten gem: "You mentioned [topic] [timeframe] ago - might be relevant now"
        - Connection: "This relates to [other topic] we discussed"
        """
```

## Phase 2: Health Correlation Engine
**Duration:** 4-5 days
**Priority:** HIGH (objective + subjective data goldmine)
**Complexity:** High

### Goal
Automatically detect correlations between health metrics (HRV, sleep, workouts) and performance/mood, then trigger proactive notifications.

### Components to Build

#### 2.1 HealthCorrelationEngine
**File:** `backend/app/services/health_correlation.py`

**Responsibilities:**
- Analyze time-series health data for patterns
- Detect correlations between metrics (sleep → workout RPE, HRV → mood)
- Generate actionable insights with confidence scores
- Trigger NTFY notifications when thresholds crossed

**Key Methods:**
```python
class HealthCorrelationEngine:
    def __init__(self, db: Session):
        self.db = db
        self.min_data_points = 10  # Minimum samples for correlation
        self.significance_threshold = 0.7  # Pearson coefficient

    async def analyze_sleep_workout_correlation(
        self,
        user_id: str,
        lookback_days: int = 30
    ) -> Optional[HealthCorrelation]:
        """
        Correlate sleep hours with next-day workout RPE.

        Logic:
        1. Get last 30 days of sleep data (AppleHealth or manual log)
        2. Get workout logs with RPE scores
        3. Match: sleep_night_N → workout_day_N+1
        4. Calculate Pearson correlation
        5. If r > 0.7 or r < -0.7 → significant correlation

        Example findings:
        - "Sleep < 6hrs → RPE +2.3 points higher (r=-0.82, p<0.01)"
        - "Sleep > 8hrs → RPE -1.5 points lower (r=0.75, p<0.05)"
        """

    async def analyze_hrv_recovery_correlation(
        self,
        user_id: str
    ) -> Optional[HealthCorrelation]:
        """
        Correlate HRV with workout performance/missed workouts.

        Logic:
        1. Get HRV data from AppleHealth
        2. Calculate 7-day rolling average and baseline
        3. Flag days with HRV < (baseline - 15%)
        4. Check workout logs on those days
        5. Detect pattern: low HRV → skipped workout or high RPE
        """

    async def detect_overtraining_pattern(
        self,
        user_id: str
    ) -> Optional[OvertrainingAlert]:
        """
        Detect early warning signs of overtraining.

        Indicators:
        - HRV declining for 3+ consecutive days
        - Sleep quality declining (< 7hrs for 4+ days)
        - Workout RPE consistently elevated (>8 for 3+ sessions)
        - Recovery notes mentioning high soreness

        Returns alert with confidence score
        """

    async def generate_recovery_recommendations(
        self,
        user_id: str
    ) -> List[RecoveryRecommendation]:
        """
        Based on current metrics, recommend actions.

        Decision tree:
        - HRV < baseline-20% AND sleep < 7hrs → "Rest day"
        - HRV < baseline-10% → "Light active recovery"
        - HRV normal but sleep < 6hrs → "Reduce intensity 20%"
        - All metrics good → "You're recovered, train normally"
        """

    async def run_nightly_correlation_analysis(
        self,
        user_id: str
    ) -> CorrelationReport:
        """
        Run all correlation analyses and store results.

        Called by scheduler at 3:00 AM (after dream processing at 2:00 AM).

        Workflow:
        1. Run all correlation analyses
        2. Store significant findings in health_correlation table
        3. If actionable (confidence > 0.8) → trigger NTFY notification
        4. Generate weekly summary report
        """
```

**Database Schema:**
```sql
CREATE TABLE health_correlation (
```

```python
async def nightly_health_correlation(self):
```

```python
class ProactiveContextService:
    async def enhance_with_historical_context(
        self,
        user_message: str,
        user_id: str
    ) -> Optional[HistoricalContext]:
        """
        Search for related past discussions.

        Logic:
        1. Extract key topics/entities from current message
        2. Search episodic memory with semantic similarity
        3. If match > 0.75 and not within last 7 days → surface
        4. Format as: "Note: You discussed [topic] on [date]"

        Example:
        User: "I'm debugging the Redis connection issue again"

        Search: "Redis connection issue debug"
        Match: Episode from July 12th (similarity: 0.83)

        Return: "Last time this happened (July 12th), you found it was
                the Docker network configuration. Want me to pull up that
                conversation?"
        """

    async def suggest_related_notes(
        self,
        current_topic: str,
        user_id: str
    ) -> List[Note]:
        """
        Auto-suggest notes when topic matches.

        Logic:
        1. Extract topics from current message
        2. Search notes by topic similarity
        3. Return top 3 if confidence > 0.7
        4. Don't suggest notes already mentioned in last 5 messages
        """

    async def surface_shadow_captures(
        self,
        project_keywords: List[str],
        user_id: str
    ) -> Optional[ShadowContext]:
        """
        Find relevant shadow mode captures.

        When user mentions a project/file, check if shadow mode
        captured related browser tabs or VS Code files.

        Example:
        User: "I'm working on the authentication module"

        Search shadow captures for: "auth", "authentication", "login"
        Find: VS Code had auth_service.py open 2 days ago
              Browser had Auth0 docs open

        Return: "I see you had auth_service.py open in VS Code 2 days ago.
                Want me to recall what you were working on?"
        """
```

```python
class ThresholdTuner:
```

## Monitoring & Metrics

### Key Metrics to Track

#### Insight Surfacing
```sql
-- Daily insight surfacing rate
SELECT
    DATE(mentioned_at) AS date,
    COUNT(*) AS insights_surfaced,
    COUNT(DISTINCT user_id) AS active_users,
    COUNT(*) FILTER (WHERE user_engaged) AS engaged_count,
    (COUNT(*) FILTER (WHERE user_engaged)::FLOAT / COUNT(*)) AS engagement_rate
FROM insight_mention_log
WHERE mentioned_at > NOW() - INTERVAL '30 days'
GROUP BY DATE(mentioned_at)
ORDER BY date DESC;

-- Most effective insight types
SELECT
    di.insight_type,
    COUNT(*) AS surfaced,
    AVG(CASE WHEN iml.user_engaged THEN 1 ELSE 0 END) AS engagement_rate
FROM dream_insight di
JOIN insight_mention_log iml ON di.id = iml.insight_id
GROUP BY di.insight_type
ORDER BY engagement_rate DESC;
```

#### Health Correlations
```sql
-- Correlation detection rate
SELECT
    correlation_type,
    COUNT(*) AS detected,
    AVG(correlation_coefficient) AS avg_correlation,
    COUNT(*) FILTER (WHERE last_notified IS NOT NULL) AS notifications_sent
FROM health_correlation
WHERE detected_at > NOW() - INTERVAL '30 days'
GROUP BY correlation_type;

-- Notification effectiveness
SELECT
    DATE(detected_at) AS date,
    COUNT(*) AS correlations_detected,
    COUNT(*) FILTER (WHERE confidence > 0.8) AS high_confidence,
    COUNT(*) FILTER (WHERE last_notified IS NOT NULL) AS notified
FROM health_correlation
WHERE detected_at > NOW() - INTERVAL '30 days'
GROUP BY DATE(detected_at);
```

#### Proactive Context
```sql
-- Context surfacing effectiveness
SELECT
    surfacing_type,
    COUNT(*) AS total_surfaced,
    AVG(confidence) AS avg_confidence,
    COUNT(*) FILTER (WHERE engagement_type = 'positive') AS positive,
    COUNT(*) FILTER (WHERE engagement_type = 'negative') AS negative,
    COUNT(*) FILTER (WHERE engagement_type = 'ignored') AS ignored
FROM proactive_engagement
WHERE surfaced_at > NOW() - INTERVAL '30 days'
GROUP BY surfacing_type;
```

## Risk Mitigation

### Risk 1: Over-Surfacing (Sara becomes annoying)
**Mitigation:**
- Conservative initial thresholds (confidence > 0.75)
- Rate limits (max 2 insights per conversation)
- Track engagement - tune down if ignored rate > 50%
- Add user preference: "Proactive level: Low/Medium/High"

### Risk 2: Poor Correlation Quality (False positives)
**Mitigation:**
- Require minimum 10 data points for correlation
- Statistical significance testing (p-value < 0.05)
- Manual review of first 50 correlations
- User feedback mechanism: "Was this helpful?"

### Risk 3: Context Relevance Issues (Wrong historical context)
**Mitigation:**
- High similarity threshold (> 0.75)
- Time decay: prefer recent discussions over old
- User can dismiss: "Not relevant" updates threshold
- A/B test to validate effectiveness

### Risk 4: Performance Impact
**Mitigation:**
- Async processing for all analysis
- Cache frequent searches
- Nightly batch processing (not real-time)
- Monitor latency - disable features if > 200ms overhead
