## Hand review (2026-07-29) — the heuristic's false positives, read against actual code

Approval was given to "do the migration." Before touching anything, read the
actual implementation of every `legacy_cognition` job instead of trusting the
keyword heuristic. Two load-bearing findings changed the plan:

**1. `kernel.ambient_turn()` has no per-wake-reason dispatch.** `wake_reason`
is used for logging/state-publishing and one reflex-triage branch
(`PROMOTED_EVENT`) — every call ends up at the same
`deliberation_engine.run(user_id, deep=deep)`. "Migrate to a kernel wake
reason" is only a *safe, mechanical* change for a job whose current body
already **is** "run deliberation" in some form. For a job with genuinely
different logic (anticipation's rule-based prep, curiosity's pursuit
selection, interoception's self-audit), folding it into `ambient_turn` today
would silently *replace* that logic with a generic deliberation call — a real
regression, not a migration.

**Ruling that resolved this (David, 2026-07-29): wake reasons shape the
context and budget of one mind — they never select different cognitions.**
Anticipation and interoception are senses: reflex-layer/Celery code whose job
is to feed events into the kernel (via salience/promotion), not to become a
branch inside `ambient_turn`. Curiosity/pursuit is explicitly deferred to Arc
4.3, not routed through new dispatch logic now. None of the three need
`ambient_turn` to grow a dispatch table. The actual remaining Arc 3.1 work is
narrower: (a) let `wake_reason` shape context/budget *within* the one
`ambient_turn` call, and (b) build the event pathway so deterministic sense
jobs can feed the kernel. Not yet started.

**2. Several `legacy_cognition` hits were the "idle"/"consolidat"/"reflect"
keyword hints matching mechanical code with no cognition in it at all**
